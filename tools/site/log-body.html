0119 Oct
Problem selection

Choose the problem on usefulness and viability

Checks
Evidence of demand. Not already shipped or on the published roadmap. Data reachable through a public API or an admin export. Value can be measured. A working prototype in two to three weeks, provable on a free trial tenant.
Not used
Fit with my own past experience.
0219 Oct
DroppedCopilot Studio

Don't build a Copilot Credits dashboard

Why
Credit totals are already shown by environment, agent, user and feature in the Power Platform admin center, per agent in Copilot Studio, in Cost management in the Microsoft 365 admin center, and through an API.
Kept
Joining credits to how each conversation ended is still a gap, but it needs paid credits to prove, so it stays a written idea for now.
0319 Oct
Problem selection

Build the leaver impact check

Why
Leavers happen everywhere, every month. Microsoft's tools act after the person has gone. The data is reachable through admin APIs, and the effect can be proven by blocking a test user and reading Power Automate's own run history.
Instead of
A SharePoint knowledge source readiness check (higher overlap risk with a Microsoft status view) and Dataverse for Teams retirement triage (strong date, thin demand).
0419 Oct
Testing

Free trial tenant only, predictions before every test

What
Microsoft 365 Business Basic trial, a trial environment with Dataverse, no paid add-ons. Every expected result is written down with a time before the test runs.
Why
Anyone can repeat it, and matching Microsoft's own screens is the only proof that counts.
0520 Oct
Testing

Flows first, agents in a second round

Why
Keeping round 1 to six flows meant the block test could run and be scored the same evening. Agents that use the maker's credentials get their own round with a new test user.
0620 Oct
Testing

Test with Block sign-in only

Why
It is usually the first thing IT does on a last day. No password reset, session revoke, licence removal or account deletion, so the result shows what one normal step does on its own.
0721 Oct
Result

Report the timing miss and the odd SharePoint run as they are

What
6 of 6 outcomes matched, but failures came within minutes, not the 90 I expected, and one SharePoint run succeeded 37 minutes after the block. Both are written up as found.
0821 Oct
Security

Browser sign-in, read-only, nothing kept outside the admin's machine

What
Sign-in that uses a code typed on another device was blocked by the tenant's security defaults, and that block is sensible, so the script uses a normal browser sign-in. It only reads. Results are written to a local folder that is never committed.
Next
Its own app registration with read-only permissions, and a version that reads an admin export file and needs no sign-in at all.
0921 Oct
Naming

Call it Leaver Impact Check

Status
See entry 10 for how the claim was narrowed after checking the admin center.
Why
Plain words for what it does. Microsoft's trademark guidelines ask third parties not to use Microsoft product names in their own product names, so the name stays independent, and compatibility is described in text only.
1021 Oct
Positioning

Claim the login view, not "Microsoft shows nothing"

Why
Maker inventory already shows each flow's owner. What it doesn't show is whose connection the flow runs on, and that decides whether it breaks. Filtering by owner flagged 5 flows; 4 broke. The tool builds next to the owner view instead of claiming there is none.
1122 Oct
Report

One page per leaver, split into "will stop" and "owned but safe"

Why
The admin's real question is what to hand over before the last day. Showing owned-but-safe flows separately explains why an owner list over-counts, and the suggested next owner starts from existing co-owners, with a reminder that co-ownership alone doesn't keep a flow running.
Demo
The public sample uses a made-up company so no data from the test tenant is published. It is rendered by the same code that runs against a live tenant.
